### 1.2 页面结构：两套组装器 → 一套组装器 + 布局标志位

改前首页与设置页各有 `compact/` 与 `expanded/` 两份组装器，逐字重复，实际差异只有「内容是否限宽居中」。改后：

- 新增 `ui/component/ContentPane.kt`：单栏内容容器，窄窗占满、宽窗限制行宽并居中；
- 840dp 阈值收敛到 `WindowSizeClass.contentMaxWidth`，不再在各组装器里重复魔数；
- 窗口尺寸类在 `{Screen}Screen` 单一位置计算后作为参数下传，组装器不再自行分派形态；
- 删除 5 个文件：两个页面的 `compact` / `expanded` 组装器，以及 `settings/component/content/SettingsContent.kt`。

净减 129 行，行为不变（宽窗仍限宽 840dp 居中）。

### 1.3 职责收敛

- 主题 / 语言弹窗与更新结果 Toast 从内容组件上提到 `SettingsScreen` 骨架：弹层与形态无关，不随布局分派重复实现；设置页组装器参数由 11 个降至 5 个。
- `SettingsContent` 删除：形态合并后它只剩三次区块调用，保留即多余的转发层。
- `HomeScreen` 去掉无消费者的 `viewModel<HomeViewModel>()` 调用。
- `SettingsClickableItem` 改由原生 `clickable` 承载点击（自带涟漪 / 焦点 / 无障碍语义），点击坐标在 Initial 阶段旁路记录，去掉了手写的 `role` / `focusable` 补齐。

### 1.4 单元测试

新增 4 个测试类共 14 个用例，全部为 JVM 单测，用内存 `FakeSettingsRepository` 替代 mock 框架，未新增依赖：

- `AppUpdateCheckerTest`：版本比较（更高 / 相同 / 缺省位补齐 / 非数字段）
- `ThemeModeTest`：持久化值解析与未知值回落
- `SettingsViewModelTest`：弹窗显隐与动效起点
- `MainViewModelTest`：仓库回流为初始状态、写入后经同一路径回到 UI

### 1.5 构建配置

| 项 | 改动 |
|---|---|
| Gradle 内存 | Metaspace 512m → 2048m（原值在 AGP + R8 + Lint 装载时耗尽，daemon 被迫重启） |
| Kotlin 守护进程 | 新增 `kotlin.daemon.jvmargs`（4g / 1g），此前未限额 |
| daemon JVM | 规范改为 25，并去掉指向 GitHub 的 `toolchainUrl`，缺版本时直接报错而非静默下载 |
| 旧开关清理 | 删除 `kotlin.incremental.android`（Kotlin 2.4 已无此属性）、`android.nonFinalResIds`（AGP 9.5 标记为 AGP 10 移除）、`android.nonTransitiveRClass`（本就是默认值）、`org.gradle.configureondemand`（incubating 且与配置缓存互斥） |
| Release 优化 | `isMinifyEnabled` + `isShrinkResources` + `getDefaultProguardFile` → `optimization { enable = true }` |
| 语言配置 | 手写 `res/xml/locale_config.xml` + 清单属性 → `generateLocaleConfig = true` + `res/resources.properties` |
| 版本巡检插件 | `includeBuild` 源码工程 → 本机仓库（`~/.m2`）消费，配置阶段 59s → 21s |

## 二、其它项目可直接照搬的配置

### 2.1 `gradle.properties`

```properties
org.gradle.jvmargs=-Xmx8192m -Dfile.encoding=UTF-8 -XX:+UseParallelGC -XX:MaxMetaspaceSize=2048m
org.gradle.parallel=true
org.gradle.caching=true

kotlin.code.style=official
kotlin.incremental=true
kotlin.daemon.jvmargs=-Xmx4096m -XX:MaxMetaspaceSize=1024m

android.useAndroidX=true
```

**不要再写**下面这些（已失效、已弃用或为默认值）：

| 属性 | 原因 |
|---|---|
| `kotlin.incremental.android` | Kotlin 2.4 的属性表里不存在，静默无效 |
| `android.nonFinalResIds` | AGP 9.5 标记为 `Deprecated`，AGP 10 移除；默认已为 true |
| `android.nonTransitiveRClass` | AGP 8.0 起默认 true |
| `org.gradle.configureondemand` | incubating，与配置缓存互斥，单模块无收益 |
| `android.enableR8.fullMode` | AGP 8.0 起默认开启，只需确保不被写成 `false` |

### 2.2 `gradle/gradle-daemon-jvm.properties`

```properties
toolchainVersion=25
```

不写 `toolchainUrl.*`：机器缺少该版本时直接报错，而不是静默从 GitHub 拉取数百兆分发包（本机曾因此卡住构建）。前提是机器已装 JDK 25，或 `JAVA_HOME` 指向它。

### 2.3 `settings.gradle.kts` 的仓库声明

```kotlin
pluginManagement {
    repositories {
        mavenLocal()                    // 仅当使用本地维护的插件时保留
        maven { url = uri("https://mirrors.cloud.tencent.com/nexus/repository/maven-public/") }
        maven { url = uri("https://mirrors.cloud.tencent.com/nexus/repository/gradle-plugins/") }
        google {
            content {
                includeGroupByRegex("com\\.android.*")
                includeGroupByRegex("com\\.google.*")
                includeGroupByRegex("androidx.*")
            }
        }
        mavenCentral()
    }
}

dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
    repositories {
        maven { url = uri("https://mirrors.cloud.tencent.com/nexus/repository/maven-public/") }
        google()
        mavenCentral()
    }
}
```

### 2.4 `app/build.gradle.kts` 片段

```kotlin
android {
    androidResources {
        localeFilters += listOf("zh", "en")
        // 由 AGP 依据资源目录生成 locale_config 并写入清单
        generateLocaleConfig = true
    }

    buildTypes {
        release {
            // AGP 9.3+：代码优化 + 优化型资源缩减 + 平台默认 keep 规则一并开启
            optimization {
                enable = true
            }
            proguardFiles("proguard-rules.pro")
            signingConfig = signingConfigs.getByName("release")
        }
    }
}
```

配套两件事，缺一构建失败：

1. 新建 `app/src/main/res/resources.properties`，内容 `unqualifiedResLocale=zh`（默认语言）；
2. **删除**手写的 `res/xml/locale_config.xml` 与清单里的 `android:localeConfig`——与 `generateLocaleConfig` 共存会被判为冲突。

### 2.5 迁移检查清单

| 检查项 | 动作 |
|---|---|
| 是否还用 `isMinifyEnabled` / `isShrinkResources` | 迁到 `optimization { enable = true }`（需 AGP 9.3+） |
| 是否有手写 locale_config | 迁到 `generateLocaleConfig` |
| 是否声明了上面 5 个旧属性 | 删除 |
| 是否用 `includeBuild` 引入本地插件 | 改为本机仓库消费（见 2.6） |
| 是否缺少 Kotlin 守护进程限额 | 补 `kotlin.daemon.jvmargs` |
| `./gradlew help` 配置耗时 | 正常应在 20s 内；明显偏高先查 `includeBuild` 数量 |

### 2.6 本地维护插件改成本机仓库消费（三步）

```bash
# 1) 插件工程加发布能力（convention 插件或模块 build.gradle.kts）
#    plugins { `maven-publish` }
#    version = rootDir.resolve("version.txt").readLines().first().trim()

# 2) 发布到本机仓库
cd path/to/plugin-project && ./gradlew publishToMavenLocal

# 3) 宿主工程改为坐标消费
#    pluginManagement { repositories { mavenLocal(); ... } }
#    plugins { id("your.plugin.id") version "1.0.1" }
```

效果：日常构建只从 `~/.m2` 读 jar，不再配置并编译插件工程。本机实测配置阶段 59s → 21s。
约束：改完插件源码要重新发布一次；换机器需先装一次。

## 三、踩坑记录

1. **AGP 9.5 新增 Compose Preview 任务**：只要 `buildFeatures.compose = true`，每个变体都会注册 `generate*ComposePreviewRunfiles`，变体未启用单元测试时任务创建即失败，导致 `./gradlew tasks` 与 IDE 同步中断。解法是 `testOptions.unitTests.isIncludeAndroidResources = true` + `beforeVariants { (it as HasUnitTestBuilder).enableUnitTest = true }`（该属性在 `VariantBuilder` 上已隐藏，必须经 `HasUnitTestBuilder`）。

2. **配置缓存暂时不可用**：条目能生成但每轮判定失效（`buildfingerprint*.tmp` 被清理），清空缓存、关闭 VFS 监听、换 Gradle 9.8.2 均复现，**不是 9.9.0 的回归**。本机暂未启用；换环境可再试。

3. **Gradle 9 已移除 `-c` / `--settings-file`**：想用"另一份 settings 做可选功能"的老办法行不通。

4. **settings 插件无法条件应用**：`plugins {}` 块不接受 `if`；`includeBuild` 提供的插件只对声明式解析可见，命令式 `apply(id)` 找不到它。这是最终选择本机仓库方案的原因。

5. **wrapper 下载超时**：Java 客户端的 10s 连接超时对 GitHub 重定向不够用。可用 curl 预置分发包到 `~/.gradle/wrapper/dists/<version>/<hash>/`（hash 为 `distributionUrl` 的 MD5 转 base36），或用镜像下载后同样放置。
